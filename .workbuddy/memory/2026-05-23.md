## 改造新增产品：图片与产品合并为单次上传

- **变更原因**：图片和产品需一起上传，后端同一接口完成图片存储 + 产品创建 + 图片关联
- **取消预上传策略**：选图后仅存本地临时路径，不再立即调用 `/api/v1/files/upload`
- **utils/api.js**：新增 `createProductWithFile(filePath, productData)` 方法，使用 `wx.uploadFile` 一次性上传文件 + formData 产品字段
- **product-form.js**：提交时根据是否有图片分流：有图调 `createProductWithFile`（multipart），无图调 `createProduct`（JSON）；抽取 `_handleError` 统一错误处理
- **product-form.wxml**：简化图片区域，移除上传中/失败遮罩状态，仅保留预览和重选提示
- **product-form.wxss**：清理不再需要的上传遮罩样式
- **docs/product-api.md**：重新提取接口文档，核心变化：
  - `POST /api/v1/products` 改为双模式接口：有 `file` 字段时按 multipart 处理，无 `file` 时按 JSON 处理
  - formData 中所有值为字符串，后端需自行类型转换（`price`→float, `is_recommend`/`is_in_stock`→bool）
  - 独立图片上传接口 `/api/v1/files/upload` 在新增产品场景中已废弃

## 修复新增产品 422 报错

- **根本原因**：前端发的字段名是驼峰（`itemNo`/`isRecommend`/`isInStock`），FastAPI/Pydantic 默认用 snake_case，导致字段不匹配触发 422
- **修复**：`product-form.js` 的 `_doCreate` 方法中，字段名改为 snake_case：`item_no`、`is_recommend`、`is_in_stock`
- **增强调试**：catch 块中新增 422 错误的详细 loc/msg 打印，Toast 提示也优化为显示具体是哪个字段校验失败
- **同步更新**：`docs/product-api.md` 所有字段名、请求/响应示例全部改为 snake_case
